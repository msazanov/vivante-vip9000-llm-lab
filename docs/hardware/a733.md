# Allwinner A733 hardware research

## Verified upstream overview

Allwinner publicly describes the A733 as a heterogeneous Arm SoC with:

- 2 × Arm Cortex-A76 CPU cores;
- 6 × Arm Cortex-A55 CPU cores;
- PowerVR BXM GPU;
- an NPU advertised at up to 3 TOPS;
- LPDDR4/LPDDR4X/LPDDR5 memory support.

These are SoC-family facts, not a guarantee of the exact clocks, memory configuration, enabled accelerators, driver versions, or thermal behavior of the target Orange Pi board.

## CPU strategy

The CPU should not be treated merely as fallback. A likely effective design is heterogeneous scheduling:

- Cortex-A76 cores: latency-sensitive scalar work, token generation, graph scheduling, sampling, unsupported high-value kernels;
- Cortex-A55 cores: background conversion, I/O, preprocessing, low-priority tasks, or parallel kernels where energy efficiency matters;
- NPU: stable, sufficiently large graph segments with supported layouts and precisions;
- GPU: explicitly out of initial scope unless evidence shows a practical path.

This division is a hypothesis. Thread affinity, scheduler behavior, memory bandwidth, and thermal limits must be measured.

## Required target capture

Create a sanitized capture script that records at least:

```bash
uname -a
cat /etc/os-release
lscpu
cat /proc/cpuinfo
free -h
cat /proc/meminfo
find /sys/devices/system/cpu/cpufreq -maxdepth 3 -type f -print -exec cat {} \;
cat /proc/device-tree/compatible 2>/dev/null | tr '\0' '\n'
dmesg | grep -Ei 'npu|vip|vivante|galcore|openvx|iommu'
lsmod
ldconfig -p
```

Also collect:

- `/proc/config.gz` or kernel config where available;
- relevant device-tree nodes;
- NPU device nodes and permissions;
- thermal zones and cooling devices;
- PMU/performance-counter availability;
- CPU governor and idle states;
- contiguous-memory/CMA reservation;
- SDK sample output.

## Memory-bandwidth considerations

LLM decode on CPU is often memory-bandwidth constrained. The project must measure rather than assume:

- sustainable CPU memory bandwidth;
- bandwidth under mixed CPU+NPU load;
- whether NPU traffic contends with CPU access to model weights;
- cost of layout conversion and copies;
- benefit of keeping a subset of weights resident or compiled into NPU graphs.

A 3-TOPS marketing figure does not determine LLM performance. Operator coverage, precision, graph-launch cost, and memory movement may dominate.

## Thermal and power considerations

Every benchmark should capture:

- ambient conditions when practical;
- board cooling configuration;
- start/end temperatures;
- CPU and NPU clock state;
- throttling events;
- input power or energy where measurable.

Results obtained during uncontrolled throttling must be labeled.
