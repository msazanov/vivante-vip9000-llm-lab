# Allwinner A733 hardware facts

This document is the canonical fact sheet. Every claim is labeled by evidence
class; legacy reports remain immutable under `docs/evidence/`.

## Evidence classes

- **Verified upstream**: an SoC-family or vendor fact from an authoritative
  source. It does not prove the exact board's population, clock, or firmware.
- **Verified on target**: a read-only observation from the Orange Pi target.
- **Verified in supplied tooling**: a host or SDK observation that does not
  prove target execution.
- **Unknown**: not measured, contradictory, or not safe to infer.

## CPU and memory

| Fact | Class | Interpretation |
|---|---|---|
| 6x Cortex-A55 plus 2x Cortex-A76 | **Verified upstream** | SoC-family topology; target policy and live clocks still require readback. |
| 32-bit external memory interface | **Verified upstream** | Interface width used for the theoretical rate calculation. |
| LPDDR5-4800 support | **Verified upstream** | Supported SoC ceiling, not proof of the board's installed DRAM speed. |
| 19.2 GB/s (`32-bit x 4800 MT/s / 8`) | **Derived upstream ceiling** | Theoretical SoC maximum only; never a measured bandwidth result. |
| 12 GB board SKU / about 11 GiB visible to Linux | **Observed on target** | Capacity and usable memory are not the same; exact population and reserved memory remain separate facts. |
| Effective LPDDR data rate | **Unknown** | No independent PHY/training readback is retained. |
| Sustained bandwidth for Bonsai decode | **Unknown** | Must be measured with a declared method; CPU PMU events are not DDR bytes. |

## Target clock and board identity

| Fact | Class | Evidence |
|---|---|---|
| Current memory-controller readback is 510 MHz | **Verified on target** | `clk_summary` and read-only register readback agree at the controller clock. |
| `PLL_DDR` parent readback is 2040 MHz | **Verified on target** | Parent clock evidence; it is not the external data rate. |
| Target exposes eight CPUs and A55/A76 policies | **Verified on target** | [`orange-pi-zero-3w.md`](orange-pi-zero-3w.md) and the DDR audit. |
| Board hostname and device-tree compatible strings agree | **Unknown** | The target label says Zero 3W while the device tree reports `xunlong,orangepi-4-pro` and `arm,sun60iw2p1`. |
| DDR devfreq is bound and selectable through Linux | **Unknown** | The observed DMC module was not bound to a `/sys/class/devfreq` node. |

The readback is intentionally stated as a controller clock. It does not prove
`1020 MT/s`, `4800 MT/s`, or any sustained GB/s value. Do not convert a
controller clock to a data rate without a source-verified PHY/training formula.

## Safety boundary

Frequency and voltage changes are constrained by the board's **secure firmware**,
vendor BSP, kernel thermal protection, watchdog/recovery behavior, and the
project's safety review. The canonical default is stock configuration. A raw
PLL or `/dev/mem` write is not evidence of a supported operating point, and a
readback is not evidence of data integrity. Any future overclock candidate must
be isolated, guarded, reversible, and separately qualified; it must not bypass
secure firmware or safety controls.
