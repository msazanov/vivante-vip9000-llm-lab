# A733 DDR PLL 600 MHz A/B Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Без постоянного изменения boot-конфигурации проверить временный DDR-кандидат 600 MHz и измерить его влияние на Bonsai-27B Q1 decode с гарантированным программным и watchdog-откатом.

**Architecture:** Fail-closed Python runner жёстко разрешает только полную пару `PLL_DDR_CTRL 0xf9005400 → 0xf9006300`, владеет watchdog, sampler, workload process groups и восстановлением. Сначала mock/unit tests и независимое ревью, затем read-only target preflight, короткий bandwidth/integrity/Q1 gate и только после него полный CPU-only Bonsai run. Все выводы строятся по JSONL evidence и прямому clock/register readback.

**Tech Stack:** Python 3.11 standard library, Linux `/dev/mem`, watchdog ioctl, `/sys`/debugfs telemetry, `unittest`, `mbw`, `memtester`, pinned PrismML Q1 CPU runner и `llama-bench`.

## Global Constraints

- Первый и единственный candidate: full word `0xf9006300`, raw `N=0x63`; original/restore: `0xf9005400`, raw `N=0x54`.
- Разрешённый writable physical address только `PLL_DDR_CTRL=0x02002020`; `DRAM_CLK_REG=0x02002c00` только читается.
- Candidate ожидается как `pll-ddr=2400000000` и `dram0=600000000`; это считается фактом только после прямого readback.
- Apply требует root, аппаратный watchdog с heartbeat, exact confirmation, полную preflight telemetry и exclusive lock.
- Любой exception, сигнал, timeout, register drift, lock loss, sampler/heartbeat/workload error или температура ≥85000 m°C останавливает workload и запускает restore.
- Restore означает write полного `0xf9005400`, bounded lock polling, exact register readback и clock readback `2040000000/510000000` до magic-close watchdog.
- Boot config, DTB/DTBO, voltage, OPP table, governor и model bytes не изменяются.
- Pinned model: `Bonsai-27B-Q1_0.gguf`, size `3803452480`, SHA-256 `17ef842e47450caeb8eaa3ebfbbab5d2f2278b62b79be107985fb69a2f819aa0`.
- Pinned runtime commit: `38c66ad0241da4f9fcce541cda8edc219086cec5`; full model использует A55 CPUs 0–5, t6, CPU-only.
- Главный success criterion — decode tokens/s без изменения deterministic output. `mbw` сам по себе не доказывает ускорение модели.
- Документация и объяснение терминов пишутся по-русски; machine-readable поля и schema identifiers остаются стабильными ASCII.

- [ ] **Step 3: Implement register backend and bounded lock contract**

Use only page-aligned `mmap` with explicit little-endian 32-bit words: a direct
target probe proved that `os.pread(fd, 4, 0x02002020)` returns `EFAULT` on this
kernel. A write attempt marks restore-required before the syscall. Both
candidate and original restore call the same bounded exact-readback function:

```python
def poll_lock(backend, expected_word, timeout_s=2.0, interval_s=0.05):
    deadline = time.monotonic() + timeout_s
    while time.monotonic() < deadline:
        value = backend.read32(PLL_DDR_CTRL)
        if value == expected_word and value & (1 << 28):
            return value
        if not value & (1 << 28):
            raise SafetyAbort("PLL lock lost")
        time.sleep(interval_s)
    raise SafetyAbort("PLL lock/readback timeout")
```
