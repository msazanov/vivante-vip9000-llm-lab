# A733 fan policy implementation plan

> Execution is tracked by Beads issue `orange-RAG-16p.3`; this document is the
> reproducible implementation plan, not a task-status checklist.

**Goal:** Persist the operator-approved 30 °C PWM-fan trip without weakening
any other thermal protection.

**Architecture:** A fixture-testable Bash helper performs a two-phase sysfs
preflight and verified write with rollback. A narrow systemd oneshot invokes
the helper once per boot.

**Tech stack:** Bash, Linux thermal sysfs, systemd, Python `unittest` fixtures.

## Global constraints

- Discover thermal zones by type, never by `thermal_zoneN` number.
- Require both CPU zones and a real `pwm-fan` binding before any write.
- Change only the fan-bound passive trip to exactly 30000 millidegrees Celsius.
- Preserve all governor, PWM, CPU-frequency, GPU, NPU, and critical-trip state.
- Refuse partial configuration and attempt rollback after a write failure.
- Keep proprietary binaries, credentials, network addresses, and board-local
  paths out of committed documentation.

## Task 1: Helper and fixture tests

Create `tooling/set_a733_fan_trip.sh` and
`tests/test_set_a733_fan_trip.py`. First add failing fixtures for success,
missing CPU zone, non-fan binding, and write/readback failure. Then implement
the smallest helper that satisfies the design and run the focused and full
test suites.

## Task 2: systemd unit and documentation

Create `tooling/systemd/a733-fan-trip-30c.service`; test its security-sensitive
fields and exact `ExecStart`. Update `tooling/README.md` and the target hardware
document with installation, verification, rollback, and the distinction
between runtime and persistent state.

## Task 3: target installation and verification

Copy the reviewed helper and unit to temporary target paths, install them as
root-owned files, reload systemd, enable and start the unit, then verify both
live trip values, fan cooling state, PWM, and unit status. Retain the commands
and output as target evidence without credentials.
