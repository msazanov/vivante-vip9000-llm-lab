# E022 Fused Q1 Dot/Reduce Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prove and benchmark a VIP9000 EVIS kernel that consumes packed Q1 signs and Q8 activations in registers, computes exact partial dots without an expanded weight tensor, and either beats E014 or records a measured rejection.

**Architecture:** Start with a host-only/raw `DP16x2_b` lane probe. Only a target-golden-proven lane mapping may enter the fused Q1 kernel. The production candidate reuses one Q8 block across four Q1 rows, computes `2*sum(bits*q)-sum(q)` in INT32, applies Q1/Q8 scales once, and returns only compact partial/final outputs.

**Tech Stack:** Vivante SDK 5.11.0 Docker image `ubuntu-npu:v2.0.10.2`, `vcCompiler`, TIM-VX/OpenVX headers, EVIS `.vx` shaders, C NBG builders, VIPLite target runner, Python unittest and JSON fixtures.

## Global Constraints

- Target is Orange Pi Zero 3W, A733, VIP9000 PID `0x1000003b`, one NPU core.
- Canonical Q1_0×Q8_0 result must match current CPU golden; no expanded Q1 `±1` tensor may be a graph input or DDR staging buffer.
- Integer accumulation uses INT32; FP16 scales are applied only after integer reduction.
- Every target run records H2D, run, D2H, device time, cycles, repeat_equal, and temperature.
- A speed claim requires exact golden and end-to-end `M1024×K5120` below E014’s `13.97 ms` baseline.
- Preserve E014/E020/E021 artifacts as control and negative results.
