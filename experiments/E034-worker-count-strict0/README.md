# E034 — число worker-потоков при `strict=0`

Дата: 2026-08-12  
Плата: Orange Pi Zero 3W / Allwinner A733  
Модель: pinned `Bonsai-27B-Q1_0.gguf`

## Зачем

После E033 (`strict=0`, 8 workers, 0.968236 ток/с) проверяем, не конкурируют
ли восемь потоков за одну LPDDR-память. `strict=0` оставлен неизменным, маска
`0xff` включает все CPU; меняется только число workers `-t`.

`n=8/r=1` — быстрый screen, а не финальное обещание скорости. Все варианты
были обёрнуты `profile_command.py` и `thermal_exec_guard.py` (85 °C).

## Screen

| Workers | Короткая скорость, ток/с | Код | Интерпретация |
|---:|---:|---:|---|
| 4 | 0.828570 | 0 | слишком мало параллелизма |
| 5 | 0.827991 | 0 | слишком мало параллелизма |
| 6 | 0.889905 | 0 | около старого baseline |
| 7 | 0.985185 | 0 | близко к максимуму |
| 8 | **0.998680** | 0 | screen winner |

В коротком screen 8 workers победили; это не было принято без длинной
проверки, поскольку memory-bound decode чувствителен к прогреву и шуму.

## Полный gate

Для 8 workers повторены параметры E033: `n=32/r=3`, F16 KV, flash on,
`batch/ubatch=512`, `poll=50`, governor `performance`, DDR raw `0x54`.

| Вариант | Samples, ток/с | Средняя скорость | Δ к E033 | Решение |
|---|---|---:|---:|---|
| E033 reference | 0.980676 / 0.964671 / 0.959361 | **0.968236** | — | текущая база |
| E034 native, 8 workers | 0.963765 / 0.965773 / 0.967243 | **0.965594** | −0.27% | rejected; в пределах разброса |

Тепловой trace E034: CPU big `72.865 °C`, little `75.284 °C`, DDR `64.790 °C`,
NPU `63.240 °C`, GPU `67.673 °C`, skin `39.056 °C`; thermal abort не было.

## Вывод

Простое уменьшение числа workers не устраняет узкое место LPDDR. Оставляем
all-core/8 workers и `strict=0`; следующий прирост нужно искать в traffic,
ядре GEMV или уменьшении H2D/D2H, а не в отключении CPU.
